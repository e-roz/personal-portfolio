# Milestone 1.1 — Project Setup Implementation Plan

> **How this plan is executed:** guided mode. **You** run every command and make every commit; Claude explains each step beforehand and reviews the result afterward. Steps use checkbox (`- [ ]`) syntax so you can tick them off.

**Goal:** Turn the empty repository into a minimal, working Astro + TypeScript + Tailwind project that builds, type-checks, and runs locally — with every file understood.

**Architecture:** Manual setup (no `npm create astro` template), so each file is created deliberately and explained, and nothing unexplained appears in the repo. One placeholder page proves the toolchain works; real layout and pages start in milestone 1.2.

**Tech Stack:** Node.js 24 (installed), npm 11, Astro 7.x, TypeScript 6.x, `@astrojs/check`, Tailwind CSS 4.x via `@tailwindcss/vite`.

**Spec:** [`docs/design/2026-11-12-portfolio-design.md`](../design/2026-11-12-portfolio-design.md) — §2 (technology), §3 (folder structure), §8 milestone 1.1.

## Global Constraints

- Node.js **≥ 22.23.4**, even-numbered major versions only (Astro requirement). You have v24.13.0 ✅.
- TypeScript **6.x**, not 7.x — `@astrojs/check` declares `typescript: "^5.0.0 || ^6.0.0"`.
- Only these dependencies: `astro`, `tailwindcss`, `@tailwindcss/vite`, `@astrojs/check`, `typescript`. Nothing else.
- File and folder names: lowercase, hyphens, no spaces (CI runs on case-sensitive Linux).
- No personal information anywhere yet; placeholder text only.
- **No commit or push without your own explicit decision.** You review `git diff --staged` before every commit. Pushing to GitHub happens only at the end, and only if you choose to.
- Work happens on branch `feat/project-setup`, never directly on `main`.
- Use **Git Bash** as your terminal for this milestone — every command is Linux-style, which is practice for your Linux studies.

## Review Focus

Failure modes not obvious from the happy path, each with a check in its owning task:

1. **Running commands in the wrong folder** (e.g. `npm init` in `F:\`) → creates stray files elsewhere. Check: Task 0 Step 1 verifies the folder.
2. **Windows CRLF line endings committed** → noisy diffs and broken shell scripts on Linux CI. Check: Task 1 Step 4 and Task 5 Step 3 (`git ls-files --eol`).
3. **`node_modules/`, `dist/`, or `.astro/` committed** → huge repo, leaked build output. Check: Task 1 Step 3 (`git check-ignore`), Task 5 Step 2.
4. **npm installs TypeScript 7** (the newest) → `ERESOLVE` peer-dependency error with `@astrojs/check`. Check: Task 3 Step 2 (`npm ls typescript`).
5. **Port 4321 already in use** → Astro silently picks another port, and you open the wrong URL. Check: Task 2 Step 7 (read the URL Astro prints).

### Task 1: Git hygiene — `.gitattributes` and `.gitignore`

> **Order change (2026-11-13):** for learning purposes this task is finished *after* Task 2, so the folders being ignored (`node_modules/`, `dist/`, `.astro/`) actually exist and can be tested. A draft `.gitignore` exists from the start, and **no `git add .`** is used until this task is committed. On a real team you would still write these files first.

**Why it matters:** these rules keep wrong line endings and junk files from ever being staged.

**Concepts:**
- **Line endings:** Windows ends lines with `CRLF` (`\r\n`), Linux with `LF` (`\n`). `.gitattributes` tells Git to store text files with `LF` in the repository, so CI on Linux sees the same bytes you wrote.
- **`.gitignore`:** lists paths Git must never track — dependencies (re-downloadable), build output (re-generatable), and secrets.

**Files:**
- Create: `.gitattributes`
- Create: `.gitignore`

- [ ] **Step 1: Create `.gitattributes`**

```gitattributes
# Store all text files with LF line endings in the repository.
* text=auto eol=lf

# Binary files: never touch line endings.
*.pdf  binary
*.png  binary
*.jpg  binary
*.webp binary
*.ico  binary
*.woff2 binary
```

`text=auto` = Git detects text files automatically. `eol=lf` = they are checked out and stored with LF.

- [ ] **Step 2: Create `.gitignore`**

```gitignore
# Dependencies (re-installed from package-lock.json)
node_modules/

# Build output (re-generated by `npm run build`)
dist/

# Astro's generated types and cache
.astro/

# Environment variables and secrets — never commit
.env
.env.*

# OS / editor noise
.DS_Store
Thumbs.db
.vscode/
```

- [ ] **Step 3: Test that the ignore rules work (Review Focus #3)**

```bash
git check-ignore -v node_modules/x dist/x .astro/x .env
```

Expected: four lines, each naming the `.gitignore` line that matched. If a path prints nothing, its rule is wrong.

- [ ] **Step 4: Test the line-ending rule (Review Focus #2)**

```bash
git check-attr text eol -- README.md
```

Expected: `README.md: text: auto` and `README.md: eol: lf`.

- [ ] **Step 5: Commit (your decision)**

```bash
git add .gitattributes .gitignore
git diff --staged --stat
git commit -m "chore: add gitattributes and gitignore"
```

### Task 2: Minimal Astro project

**Concepts:**
- **`package.json`:** the project's manifest — name, scripts (shortcuts like `npm run dev`), and dependencies.
- **`package-lock.json`:** records the *exact* version of every installed package, so CI and your laptop install identical code. Always committed.
- **`"private": true`:** prevents accidentally publishing this project to the public npm registry.
- **`"type": "module"`:** tells Node to use modern `import`/`export` syntax.
- **`engines`:** documents the required Node version; CI will rely on it later.

**Files:**

### Task 3: Type checking with `astro check`

**Concepts:**
- **`astro check`** reads every `.astro` and `.ts` file and reports type errors without building. It exits with code `1` on errors — that is what will make CI fail in Phase 4.
- **Peer dependency:** a package saying "I need *you* to install X in a compatible version". `@astrojs/check` requires TypeScript 5 or 6. TypeScript 7 is the newest release, so a plain `npm install typescript` would pick 7 and fail. We pin `@6`.
- **devDependencies:** tools needed only while developing/building, not by the site itself.

**Files:**
- Modify: `package.json` (new `devDependencies` and `check` script)
- Modify: `package-lock.json` (by npm)

### Task 4: Tailwind CSS

**Concepts:**
- **Tailwind** generates CSS from class names you use (`text-3xl`, `font-bold`). At build time it scans your files and outputs only the classes actually used.
- **Vite** is the build tool Astro runs on. `@tailwindcss/vite` is a Vite *plugin* — it hooks into Astro's build to generate the CSS.
- **`@import "tailwindcss";`** pulls in Tailwind's base styles (a CSS reset called *preflight*) plus the utility classes.

**Files:**
- Modify: `package.json`, `package-lock.json` (by npm)
- Modify: `astro.config.mjs`
- Create: `src/styles/global.css`
- Modify: `src/pages/index.astro`

- [ ] **Step 1: Install Tailwind and its Vite plugin**

```bash
npm install tailwindcss @tailwindcss/vite
```

- [ ] **Step 2: Register the plugin in `astro.config.mjs`**

```js
// @ts-check
import { defineConfig } from "astro/config";
import tailwindcss from "@tailwindcss/vite";

// https://docs.astro.build/en/reference/configuration-reference/
export default defineConfig({
  vite: {
    plugins: [tailwindcss()],
  },
});
```

- [ ] **Step 3: Create `src/styles/global.css`**

```css
@import "tailwindcss";
```

Design tokens (colours, fonts) are added to this file in milestone 1.2.

- [ ] **Step 4: Import the stylesheet and use a Tailwind class in `src/pages/index.astro`**

```astro
---
// Frontmatter: runs at build time, never in the visitor's browser.
// In milestone 1.2 this import moves into BaseLayout.astro.

const title = "Portfolio — under construction";
---

<html lang="en">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <title>{title}</title>
  </head>
  <body>
    <h1 class="text-3xl font-bold">{title}</h1>
  </body>
</html>
```

Expected: the heading is now large and bold, and the default browser margins are gone (that is preflight). Stop with `Ctrl+C`.


Expected: at least one file path printed (a `.css` file in `dist/_astro/` or `dist/index.html` if the CSS was inlined). Nothing printed = Tailwind is not running.
